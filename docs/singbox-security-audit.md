# sing-box 配置与网络接管安全审计

日期：2026-11-17。范围为当前桌面 GUI 使用的配置生成器、Windows TUN、系统代理及连接生命周期。
官方版本、字段语义和固定源码依据见[官方依据审计](singbox-official-reference-audit.md)。

## 结论

当前实现具备符合官方配置格式的 TUN、DNS 劫持和明确的 VPN 出口策略，本轮修正了已复现的分流、状态和代理恢复问题。
**不能据此认证整机、所有应用、所有网络和崩溃期间均无 IP / DNS 泄漏。**
系统代理覆盖范围、分流模式的直连策略、上游例外、Windows 路由限制和没有持续断网保护，都是实际保护边界。

本轮保持桌面 GUI 管理内核的现有架构，不恢复已经移除的后台服务或持久 WFP 策略。
开发验证没有启用本机 TUN、修改系统代理、DNS、路由或防火墙，也没有连接公网 VPNGate 节点。

## 配置与修复

| 项目 | 核对结果与本轮处理 |
| --- | --- |
| TUN | 保留 IPv4/IPv6 地址、`auto_route`、`strict_route`、`auto_detect_interface`；显式写出 1.14 已支持、原本默认启用的 `dns_mode: hijack` |
| 内核兼容 | 省略已经弃用的 `stack`、`dns.independent_cache`；保留 1.14 的 gVisor 能力要求，允许使用新原生栈的官方 1.15 Alpha |
| VPN DNS | `vpn-dns` 明确 `detour: vpngate`；远端 VPN 域名引导解析经过 `upstream`；没有业务 VPN 失败后改用直连解析器的自动回退 |
| 域名分流 | 生产分流模式在域名规则之前进行 HTTP/TLS/QUIC 嗅探；修正缓存 IP 缺少 DNS 反向映射时黑名单 TLS 流量直连的问题；不改写原始目标 IP |
| 内网名称 | 普通业务的 `localhost`、`.local`、`.lan` 只使用 hosts；未知名称失败，不再发送公网 DNS；直连出站前也显式按该解析器解析，避免绕过 DNS 规则 |
| 设置生效 | 活动连接的新设置先做前置检查，再与替换运行状态一起持久化；前置失败保留旧连接及旧策略，避免显示“全局”而实际仍是旧直连策略 |
| 上游进程例外 | 自动发现的路径只用于本次运行配置，每次重新连接重新识别；不再自动保存成永久的手工直连例外 |
| 上游进程识别 | 同时核对监听地址与端口，不再将其他回环地址或局域网地址上恰好同端口的程序加入直连例外 |
| 系统代理失败恢复 | 保存旧、新两个可能生效的本应用代理端点，完成持久化后才提交新所有权；切换中途失败仍可恢复，第三方后来设置的代理保持不动 |
| PAC / WPAD | 桌面模式通过 WinINet 查询原始 LAN 连接标志并保存，使用正式连接选项禁用自动代理标志；恢复时校验用户 SID，先恢复标志，最后恢复代理服务器；旧服务路径不调用当前用户 API |

系统代理连接标志采用 Microsoft 的 `INTERNET_PER_CONN_FLAGS_UI` 查询及
`INTERNET_PER_CONN_FLAGS` 设置/恢复语义，见
[官方连接选项](https://learn.microsoft.com/en-us/windows/win32/api/wininet/ns-wininet-internet_per_conn_optionw)。
自动化覆盖原生结构体布局和各失败点的恢复顺序；它没有执行本机代理写入，实际 Windows 选项生效仍需现场验收。

## 必须保留的保护边界

| 使用方式 | 实际边界 |
| --- | --- |
| 全局 + TUN | 被 TUN 捕获、未命中上游/私网例外的公网业务流量走 VPN；本实现对不支持的 VPN IPv6 分支明确拒绝 |
| 绕过大陆 | 匹配大陆域名的业务及 DNS 有意直连；无法识别的公网目标按 VPN 默认出口处理 |
| 黑名单 | 只有识别并匹配黑名单的目标走 VPN；未知 IP、未列出域名、隐藏域名的加密流量可能直连；嗅探不能把它变成全局模式 |
| 直连 | 公网业务和对应解析有意直连，不提供出口隐藏 |
| 仅系统代理 | 只覆盖主动采用该代理的应用；不能覆盖所有 DNS、UDP、WebRTC、服务和应用自定义网络栈 |
| VPN 隧道不可用、内核还在运行 | VPN 分支返回错误或由离线配置拒绝，不自动选择直连；分流模式的直连分支仍按原策略工作 |
| 内核或 GUI 退出、重建 TUN | 没有跨进程的持续断网保护；系统路由消失时，未受其他防火墙保护的流量可能恢复物理网络出口 |

桌面版启动或重建 TUN 时，按配置的本机监听地址和端口自动识别上游代理进程。该进程的连接可命中进程直连规则，
因此应使用专用代理程序。远程上游通过 sing-box 的默认接口拨号，桌面版不会将旧配置中的进程路径写入分流规则。

直连解析器目前仍是 TCP `223.5.5.5:53`。TCP 不等于加密 DNS；直连/分流/上游引导等例外的查询
仍可能被本地网络及解析器观察。VPN 内 TCP DNS 在本机至 VPN 节点间有隧道保护，出口至解析器间仍为普通 DNS。
SOCKS4 管理请求按该协议使用本机 IPv4 解析，不能将它描述为远程 DNS；需要代理端解析时使用 HTTP、SOCKS4a 或 SOCKS5。

hosts-only 不提供动态的局域网 DNS / mDNS 发现。需要访问的内部名称应存在于受控的系统 hosts 中，
未知名称会失败，避免将内部名称交给公共递归 DNS。外部上游连接自身的显式引导解析不属于普通业务规则：
如果将上游地址配置为内部域名，需单独确认其解析与信任边界；默认数值回环地址没有该域名引导问题。

Windows 系统 DNS 可能由系统 DNS Client 服务代发，外部上游的进程规则不能保证总能识别原始调用者。
上游启动、DNS 缓存为空和 TUN 已接管的组合需单独实测；不能为绕过这种问题而广泛豁免系统服务。
官方还明确保留了 Windows TunnelVision / DHCP 高优先级路由的风险，见
[官方说明](https://sing-box.sagernet.org/manual/misc/tunnelvision/)。

## 验证范围

验证使用两个独立、官方发行的 Windows amd64 内核：稳定版 **1.14.4** 和预发行版 **1.15.0-alpha.13**。
Alpha 包 SHA-256 与官方发布资产 digest 核对一致：
`7cff6a39687a12d51b289bd57a203723629eb8fd42f6668601b4484456436bc9`。
下载只进入构建验证缓存，不改变用户已选择的运行内核。

本轮已执行并通过：

- `go test -race ./... -count=1`，启用稳定版官方配置检查及原生回环；最后的 SID 升级修正另行通过全部代理/WinINet 定向 race 回归。
- `go vet ./...`。
- 两个内核各 9 组生成配置检查：四种模式的在线/离线配置，以及独立测速配置。
- 两个内核上的五种 OpenVPN 上游回环、认证失败分类、IPv4/IPv6 缓存 IP 黑名单、hosts-only DNS 功能回归。
- Windows 代理端口切换各写入失败点、PAC/WPAD 标志、当前用户身份、自动发现监听地址以及代理恢复重试回归。
- `VPNGATE_TEST_WININET_QUERY=1` 的当前 Windows 用户 LAN 标志只读查询和 amd64 ABI 检查；没有调用代理设置写入 API。
- 前端 70 项测试、类型检查与生产构建。
- `scripts/build-vpngate.ps1` 完整构建及分发文件 SHA-256 校验；修复后的 GUI 位于
  `build/bin/singbox_vpngate-gui-windows-amd64/singbox_vpngate.exe`，未自动运行或接管网络。

原生回环测试运行真实内核，但使用临时证书、受限本地代理、内部 OpenVPN 网络栈和本地 DNS/HTTPS 服务。
黑名单回归先观察到修复前的 TLS SNI 直连，再验证修复后拒绝；未列出的 TLS 名称保持原始目标。
IPv6 文档地址用作路由元数据测试，不代表已经检验真实 Windows IPv6 网卡接管。

多网卡、物理接口抓包、真实 IPv6、DoH/DoT、QUIC/STUN、休眠、重连和崩溃场景仍需隔离环境验收。
完整步骤见[使用与验收说明](vpngate-acceptance.md#ip-and-dns-leak-acceptance)。
测试、构建和 `sing-box check` 不能替代这些现场验证。
